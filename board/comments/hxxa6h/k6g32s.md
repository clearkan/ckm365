Done. The board is OIF and `oifmd validate board` reports 50 issues, 129
comments, 0 errors, 0 warnings.

Every mapping in this issue was followed: one Markdown file per issue named
`<slug>-<id>.md`, `status` and `column` deleted so the directory is the only
place state lives, the inline `history` list split into one comment file per
entry under `comments/<issue-id>/` with `event` riding along as an extra key,
and `description` promoted to the body so an issue reads as a document.

Three decisions worth recording:

**Ids are derived, not random.** This issue asked for that if the migration
might run more than once, and it was worth doing: the id is the first six
characters of a SHA-256 of the old key mapped onto OIF's alphabet. Verified
by running the whole migration twice from the same source — both runs
produce byte-identical files. Also checked for collisions across all 50
issues and all 129 comments before writing anything: none.

**`CKM-NN` survives in `aliases`,** as this issue required, because the old
keys are referenced throughout the code, docs, CHANGELOG and commit history.
`resource: oif:ckm/<id>` carries the spec-shaped reference alongside it, so
both the human key and the OIF identifier resolve. `depends_on` holds OIF
ids with the old keys kept beside it in `depends_on_aliases`.

**`updated_at` was dropped** along with `status` and `column`, on the same
reasoning this issue gives for those: the newest comment already carries it,
and holding it twice lets the two disagree.

Two things the spec caught that a hand-migration would have shipped:
`kinds` needed an explicit `contains` before CKM-42 (a feature) could sit
under CKM-41 (a task) — that decision-ticket-spawns-build-ticket shape is
how this board actually works, and it is now declared rather than implied.
And the `.gitkeep` files in the empty columns became redundant once every
column had a `column.md`, so they went.

Not done here: the `about` entries carrying `mid:` resources that this issue
names as the motivation. That needs CKM-49's `mid:` work on the export side
first — there is nothing to cite until records carry stable message ids.
