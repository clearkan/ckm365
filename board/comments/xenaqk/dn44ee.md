Fixed and shipped in 2.7.0. ROOT CAUSE was neither half of the question in this ticket: create_reply_draft DID write the fence and revise_draft DID look for it correctly - Exchange threw it away in between. The fence was a pair of HTML COMMENTS, and Exchange strips every comment inside <body> when it stores a body. Measured on both tenants, PATCH then GET: a comment and a conditional comment vanish; an id, a class and a data- attribute on a real element survive verbatim. So the fence was gone the moment the draft was saved, on EVERY draft ckm365 had ever composed since CKM-42 - not just replies (create_draft and create_forward_draft share the helper), and verify_message had been saying so all along with boundary "quote". FIX: the fence is now a pair of empty sentinel divs, modelled on the appendonsend marker Graph itself uses. POLICY: revise_draft now REFUSES an unfenced draft instead of silently inserting - this ticket asked for exactly that, and it is right now that the fence actually survives; insert_if_unfenced=True opts back in for an Outlook-composed draft. VERIFIED: scripts/draft-cycle-smoke.py passing live on BOTH tenants for the first time ever (boundary=fence, revision replaces in place, zero residue); it printed boundary=quote and WRITE SMOKE FAILED against 2.6.0, which is how the fix was confirmed rather than assumed. tests/test_live.py 14 passed on both tenants. Offline 156 passed / 15 skipped, including a new regression test whose PATCH mock strips in-body comments the way Exchange does - confirmed it fails against the old comment fence and passes against the new one. THE DEEPER LESSON, recorded in AGENTS.md: every other offline mock echoes the PATCHed body back unchanged, which is how 153 green tests sat on top of a loop that had never once worked live. TWO SEPARATE DEFECTS FOUND WHILE VERIFYING, both fixed here: verify_message["signature"] was always false for a ckm365-applied signature (same root cause), and verify_message["quoted_thread"] was a false negative on any reply to a PLAIN-TEXT original, because Graph seeds those with <div class="PlainText"> and none of the five markers it knew.
